NetScope — Privacy Policy

Last updated: November 19, 2026

Summary

NetScope captures the API traffic of the pages you open it on and keeps it on your own machine. It has no analytics, no telemetry, no error reporting and no accounts, and it never contacts the developer.

Data leaves your machine in exactly two ways, both started by you:

  1. An AI assistant (optional): Kimi or Muse — when you have connected one, consented, and ask a question, excerpts of the captured traffic are sent to it: to Moonshot AI for Kimi, or, for Muse, typed into a side chat of your own Muse account at muse.ai (Meta).
  2. Requests you send — when you, the AI at your request, or a flow you saved sends an HTTP request, it goes to the URL that request names, like any request your browser makes.

What NetScope captures

On every page, a content script wraps the page's fetch, XMLHttpRequest and WebSocket at load and mirrors their activity to the extension: request method, URL, the headers the page set, request body, response status, headers and body (up to 256 KB each), and WebSocket frames. Native behavior is unchanged. Requests the browser makes on its own (documents, images, scripts) are not captured.

The same script records the page's console: messages of every level with the file and line that logged them, uncaught errors and unhandled promise rejections with their stack, failed resource loads, Content Security Policy violations, and the URLs a single-page app navigates to. Messages are copied as text (objects as a short preview, without running their getters).

When you open the App tab, or the AI asks, NetScope reads more from the page you are on — only then, and only from that tab: its framework and version, routes, rendered components, client state (for example a Redux store or window.__INITIAL_STATE__), local and session storage, IndexedDB databases and records, Cache Storage, service worker registrations, the cookies the browser sends to the page (including HttpOnly cookies, through the cookies permission), a semantic outline of the DOM, and the list of scripts. To show the code, the background worker downloads the scripts the page loaded and their source maps from the same URLs, with the browser's cookies; they are kept in memory only, never on disk, and dropped when the worker stops. Reading is strictly read-only: NetScope writes no storage, cookies or databases of the site.

Once you open NetScope on a tab, it also records every request that tab makes — the page document, scripts, styles, images, fonts, frames, beacons and Web/Service Worker requests — through Chrome's observe-only webRequest API: URL, method, type, status, timing, cache and IP, and the request and response headers, including Cookie and Set-Cookie. No bodies. Tabs where you never opened NetScope are not recorded. The page hook also keeps, in the page's own memory only, Web Vitals and long-task timings, the workers the page starts and its EventSource streams; the App tab and the AI read them on demand.

Where it is kept:

  • Capture log, console and page requests — in the extension's IndexedDB on your machine, per tab. A new page load starts a fresh log unless you turn on Keep logs. A tab's log is deleted when the tab closes, and the whole database is wiped each time the browser starts. Each tab keeps at most the last 3,000 entries, 2,000 console messages and 4,000 page requests.
  • Conversations — every chat, including the traffic excerpts and tool results it contains, in the extension's IndexedDB until you delete it from History.
  • Docs — markdown notes the AI or you write in the Docs tab, in the extension's IndexedDB until you delete them. The AI is told never to put tokens or cookies in docs, but a doc holds whatever was written into it.
  • Flows and run history — in chrome.storage.local; flow memory, collections and checkpoints — in the extension's IndexedDB. All stay until you delete them. Collections hold whatever data a flow's collect steps save from API responses (up to 100,000 items each); clear or export them from the flow card. A paused run keeps a checkpoint (its variables and progress) until it finishes or you discard it. A flow built from a captured request stores that request's headers, which can include authorization tokens. Run history keeps step outputs (up to 4 KB each) for the last 15 runs.
  • Settings and API key — in chrome.storage.local (below).

Nothing is written outside your Chrome profile. No chrome.debugger is used.

Export and import

Settings → Your data → Export saves a JSON file through your browser's normal download: your conversations, flows with their memory and collections, docs and settings. The API key is included only if you tick that box. The file can contain captured tokens and personal data; NetScope never sends it anywhere. Import reads a file you choose and merges it in locally.

Kimi (optional AI assistant)

Off by default. Nothing is sent until you enter a Moonshot API key, tick the consent box and click "Save and enable". After that, when you ask a question or use a quick action, NetScope sends to https://api.moonshot.ai/v1/chat/completions:

  • your question and the conversation so far,
  • the parts of the captured traffic the model asks for through its tools — URLs, headers, request and response body fragments, WebSocket payloads,
  • what its inspection tools read from the page you are on — console messages, storage values, cookies, IndexedDB records, app state, the DOM outline, styles, handlers, accessibility and performance reports, feature flags, recorded page requests with their headers, and code from the page's scripts and source maps,
  • the results of requests and flow runs it performs for you,
  • a short summary of the capture (counts, hosts, status codes).

AI steps inside a flow send their prompt — including any values the prompt pulls in from earlier steps — to the same endpoint, each time the flow runs, on schedule or not.

This can include personal data, session tokens, cookies and anything else the page transfers. Only use Kimi on traffic you are permitted to share. Requests use your key and are governed by Moonshot AI's privacy policy. NetScope's developer receives nothing.

Every tool call appears in the chat and expands to the exact data that was sent.

Masking

Off by default. Mask secrets before sending replaces the values of Authorization, Cookie and common API-key headers with shape hints (for example <redacted Bearer JWT, expired 3m ago>) and scrubs token-shaped strings from bodies and URLs. Also mask emails, card and SSN patterns scrubs those too. Masking is best-effort pattern matching and cannot catch a secret in an arbitrary JSON field. Masked values are never sent by Kimi's requests: to replay a request with real credentials it references the captured entry, and NetScope copies the values locally without showing them to the model. With masking on, the inspection tools also hide every cookie value and the values of storage keys whose names look secret (token, auth, session, password, API key…).

Your API key

Stored with chrome.storage.local on this machine only — never chrome.storage.sync. It is sent only as the Authorization header to api.moonshot.ai (including the free GET /v1/models call behind "Test key"). It is never included in exports, cURL commands or copied text. chrome.storage.local is not encrypted; prefer a key with a spend cap, and use Forget key to remove it.

Muse (optional AI assistant)

Off by default. Muse is Meta's AI agent at muse.ai. NetScope has no Muse API key and never sees your Meta password: you sign in at muse.ai yourself, in a normal tab, and keep it open. Nothing is sent until you pick Muse in Settings, tick its consent box and click "Save and enable".

After that, the same data listed for Kimi above — your question, the conversation, the parts of the capture the model asks for, the results of requests and flow runs, a capture summary, and the prompts of AI steps in flows — is typed by NetScope into a side chat in your Muse account: a small script on https://muse.ai fills the message box and presses Send, and Muse's reply is read back from that tab. Every question, and every AI step in a flow, gets a fresh side chat, which NetScope archives once the answer is read. These messages stay in your Muse history (under archived chats) and are governed by Meta's terms and privacy policy for Muse, including its "Help improve our AI models" setting (Muse → Settings → Data controls), which decides whether Meta may use them to train its models. NetScope asks Muse not to save anything from these side chats to its memory, but cannot switch Muse's memory off. Only use Muse on traffic you are permitted to share.

NetScope only presses Muse's Send and Stop buttons, and Archive in the menu of its own finished side chats. It never deletes anything, never approves actions Muse asks you to approve, and reads nothing from your Muse account beyond the replies in its own side chats. While a question is in progress it stores, on this machine, which side chat that question is using. Masking (above) applies to Muse the same way.

Requests and flows

When you click Send in Edit & send, the AI (Kimi or Muse) sends a request (on autopilot, or after your approval), or a flow runs, the background worker sends that request to its URL with the browser's own cookies for that site, and records it in the tab's capture log. A request marked from the page is instead sent from inside an open tab on that site (NetScope runs a small script in the tab to do it), so it carries that page's origin, cookies and page scripts; the response stays on your machine like any other. Scheduled flows run with chrome.alarms while Chrome is open, without further interaction, until you change their schedule to "Manual only" or delete them. A flow with a page-request trigger reads the matching captured response (status, headers, body) of the page you are on and runs, at most once per its cooldown, until you pause or delete it; requests NetScope itself sends never trigger flows. A flow's memory (values it saves with set → state) is kept in the extension's IndexedDB until you clear it from the flow card or delete the flow. By default the AI works on autopilot: it sends requests and saves, runs and deletes flows without asking, and every action appears in the chat and the Traffic list. Settings → "Ask before … acts" can require your click for requests that can change data (POST, PUT, PATCH, DELETE), requests to hosts the page never used, flows that run by themselves or change data, and deleting flows — or for every request.

Permissions

  • Content scripts and host permission on <all_urls> — the capture hook must be in place on whichever page you choose to debug, and requests and flows must reach whichever API you point them at. Narrow the patterns in manifest.json to limit this. A separate script on https://muse.ai/* does nothing unless you use Muse; NetScope finds your open muse.ai tab by its address when you do.
  • storage — settings, API key, flows and run history (local); chat per tab (session).
  • alarms — flow schedules.
  • scripting — injects the capture hook into tabs that were already open when you first click the icon, sends "from the page" requests inside the site's tab, and adds the Muse script to a muse.ai tab that was open before NetScope was installed or updated.
  • unlimitedStorage — lets flow collections grow past Chrome's default storage quota.
  • clipboardWrite — the Copy buttons.
  • cookies — reads the cookies the browser sends to the page you are inspecting (including HttpOnly ones) for the App tab and the AI. NetScope never sets or deletes cookies.
  • webRequest — observes (never blocks or changes) the requests of tabs where you opened NetScope, so the App tab and the AI see documents, scripts, images and worker requests with their headers.

Data collection

NetScope collects no personal information, browsing history, usage statistics or identifiers for its developer. There is no remote code: all code ships in the package, and responses from Moonshot, from Muse and from APIs you call are rendered as text, never executed.

Limited Use

NetScope's handling of user data complies with the Chrome Web Store User Data Policy, including its Limited Use requirements. Captured traffic is transferred to Moonshot AI (Kimi) or to Meta (Muse) only when you have enabled that AI, and only to provide the feature you invoked. It is not sold, not shared with anyone else, and not used for advertising, creditworthiness or any other purpose.
