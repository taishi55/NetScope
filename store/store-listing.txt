CHROME WEB STORE — DETAILED DESCRIPTION  (paste into "Description")
========================================================================

Chrome's Network panel filters by URL. NetScope searches what actually came back.

NetScope lives in Chrome's side panel — no DevTools needed. Press Start on any tab and it indexes everything the page transfers: response bodies, request bodies, headers on both sides, and every live WebSocket frame, all searchable in one place while you keep browsing.

SEARCH INSIDE RESPONSES
Type a value, an ID, or an error string and instantly see which request returned it. Plain text or regex, case toggle, and per-field scopes (url, request headers, request body, response headers, response body, WebSocket frames) so you can search exactly where you mean. "Found in" chips on every row show where each hit lives, matches are highlighted in the detail pane, and Enter jumps to the next matching request.

WEBSOCKETS AS FIRST-CLASS CITIZENS
Every sent and received frame is captured live, tagged by direction, timestamped, and fully searchable. Inspect individual frames with pretty-printed JSON and match highlighting.

COPY AS CURL
Reproduce any captured HTTP request outside the browser in one click — method, real browser headers (cookies included) and body, properly shell-escaped. For WebSockets, get ready-made websocat and wscat commands plus a cURL handshake probe.

EXPORT ASYNCAPI 3.0
Turn captured WebSocket traffic into an AsyncAPI 3.0 skeleton: servers, one channel per socket, send/receive operations, and real captured payloads embedded as message examples. Document an undocumented realtime API in seconds.

A NOISE-FREE LIST
Repeated requests with the same input — polling, heartbeats, retries — collapse into a single row with a ×N counter by default. If the grouped responses came back with different statuses, the badge turns amber and the detail pane shows a per-status breakdown, so an intermittent 500 never hides. Toggle "Group duplicates" off to see every occurrence.

HOW CAPTURE WORKS
NetScope uses Chrome's own debugging protocol — the same one DevTools uses — attached only to the tab you choose, only while you're capturing. Chrome shows its standard "started debugging this browser" notice during capture; it disappears the moment you press Stop or close the panel. No content scripts are injected into pages and the extension requests no access to website data.

PRIVACY
Everything stays on your machine. NetScope makes no network requests of its own, sends nothing anywhere, and stores nothing. Captured traffic lives in memory only while the panel is open.

NOTES
- One tab is captured at a time; traffic before you press Start isn't seen.
- Browser-internal pages (chrome://, the Web Store) can't be captured.
- Generated cURL commands include your cookies and auth headers verbatim — treat them as secrets.

Open source and lightweight: no frameworks, no analytics, no background activity except while you're capturing.

========================================================================
PRIVACY / REVIEW FORM — SUGGESTED JUSTIFICATIONS
========================================================================

Single purpose:
Developer tool that captures the network traffic of a user-chosen tab (HTTP bodies, headers, WebSocket frames), lets the user search it in the side panel, copy requests as cURL, and export WebSocket traffic as AsyncAPI.

Permission "sidePanel":
The entire user interface is a Chrome side panel.

Permission "debugger":
The capture mechanism. The extension attaches the Chrome DevTools Protocol (Network and Page domains) to a single tab, only after the user presses "Start capture", to read request/response data and WebSocket frames for local display. It detaches when the user presses Stop, closes the panel, or closes the tab. Chrome's debugging notice bar is visible for the entire capture, so the state is never hidden from the user.

Permission "tabs":
Read the active tab's title and URL to label what is being captured in the panel and to refuse browser-internal pages.

Permission "clipboardWrite":
Used only when the user clicks a Copy button (copy as cURL, copy a frame payload, copy the AsyncAPI document).

Host permissions:
None requested. No content scripts.

Remote code:
None. All code is packaged with the extension.

Data usage:
No user data is collected, stored, or transmitted. All captured traffic remains in memory on the user's machine and is discarded when capture stops.
