CHROME WEB STORE — DETAILED DESCRIPTION  (paste into "Description")
========================================================================

Click the icon on any page and ask Kimi or Muse about the API it's calling. Send requests from cURL like Postman. Turn a sequence of calls into a flow that runs every hour.

NetScope opens a popup right on the page, starting on a chat with Kimi. No DevTools needed.

CHAT WITH YOUR PAGE'S API
Ask what an endpoint does, why a request failed, or how the whole API fits together. Kimi works through purpose-built tools instead of a giant prompt: it groups endpoints by normalized path, searches bodies, diffs a failed request against a successful one, and cites the requests it used so you can click straight to them. Choose Kimi K3.1 Pro, K3.1 Pro Highspeed or K3, and how deeply it thinks.

OR USE MUSE, WITH NO API KEY
Prefer Meta's Muse? Sign in at muse.ai in a tab, keep it open (minimized is fine), and pick Muse in NetScope. NetScope talks to Muse in its own side chat, runs the same tools, and shows the answer right on the page.

CALL APIS LIKE POSTMAN
Paste a cURL into the chat and Kimi runs it and explains the response, or ask it to replay a request the page made with different parameters. Or do it yourself: Edit & send turns any captured request into an editable cURL with a Send button. Requests run from the extension, so CORS doesn't get in the way. Kimi works on autopilot by default; one setting makes anything that changes data wait for your click.

AUTOMATE FLOWS AND BUILD SMALL BOTS
Describe it — "whenever this page loads orders, post each new paid one to my webhook, never the same one twice" — and Kimi builds it from requests the page already made, runs it once to prove it works, then turns it on. Flows go beyond a sequence of calls: filter results, loop over them, page through APIs, branch with if/else, remember what was handled between runs, call Kimi mid-flow, and run on a schedule or whenever the page makes a matching request. Big jobs are built in: flatten and de-duplicate paged results, enrich them with up to 10 parallel requests that back off on 429s, keep results in collections you can export as CSV or JSON, and let long runs pause and resume by themselves. Endpoints that reject replays (WAF, anti-bot, CSRF) can be called from inside the page itself. Copy any flow as a Markdown document with secrets masked.

CONVERSATIONS AND DOCS THAT STAY
Every conversation is kept and searchable in History; edit or retry any earlier question. Each answer's working steps fold into one line you can expand. Kimi keeps markdown docs of what it learns about an API — endpoints, auth, quirks — and you can export everything (conversations, flows, docs) to move to another browser.

KEEP LOGS ON RELOAD
One switch keeps the captured traffic — and your conversation — across page reloads and navigations.

SEARCH EVERYTHING THE PAGE SENT AND RECEIVED
Full-text or regex search across URLs, headers, request and response bodies and live WebSocket frames, with per-field scopes and highlighted matches. Repeated requests group into one row with a ×N counter. Export WebSocket traffic as an AsyncAPI 3.0 skeleton.

EXPANDABLE
A compact panel, a large split view, or a pill with a live traffic trace.

PRIVACY
No analytics, no telemetry, and the developer never receives anything. Data leaves your machine only when you ask: Kimi (off until you add your own Moonshot API key and consent) or Muse (off until you pick it and consent; it works through your own signed-in muse.ai tab) receives your questions and the traffic excerpts it needs; requests and flows go to the URLs they name. Optional masking hides secret headers, cookies and token-shaped strings from Kimi. Your API key stays in this browser profile and is never synced.

NOTES
- Captures the page's own fetch, XHR and WebSocket traffic; reload pages that were open before installing.
- Scripts cannot set Cookie, Origin, Referer or User-Agent headers; the browser's own cookies are sent instead.
- Bodies are captured up to 256 KB; each tab keeps the last 3,000 entries.
- cURL commands include captured auth headers verbatim — treat them as secrets.

Open source, no frameworks, no build step.

========================================================================
PRIVACY / REVIEW FORM — SUGGESTED JUSTIFICATIONS
========================================================================

Single purpose:
Developer tool for working with a web page's API: it captures the page's fetch/XHR/WebSocket traffic into an in-page popup, lets the user search it, resend requests (from cURL or captured requests), automate multi-step request flows on a schedule, and optionally ask an AI assistant about all of it — Kimi with the user's own API key, or Muse through the user's own signed-in muse.ai tab.

Permission "unlimitedStorage":
Lets the results a user's flows collect (their "collections") grow past Chrome's 10 MB default for extension storage. Stored locally only.

Permission "storage":
Settings, the user's Moonshot API key, saved flows and their run history (chrome.storage.local, never sync), and the per-tab chat (chrome.storage.session).

Permission "alarms":
Runs the user's saved flows on the schedule the user chose.

Permission "scripting":
Injects the capture hook and popup into tabs that were already open before the extension was installed, when the user clicks the toolbar icon; and, when the user chooses "send from the page" for a request, runs that request inside an open tab on the target site.

Permission "clipboardWrite":
Used only when the user clicks a Copy button (cURL, payload, AsyncAPI document, assistant reply).

Host permission and content scripts on "<all_urls>":
Chrome has no API for reading response bodies or WebSocket frames outside DevTools, so a small hook wraps fetch, XMLHttpRequest and WebSocket at document_start on whichever page the developer wants to work with, which cannot be known in advance. The host permission lets the user's own requests and scheduled flows reach whichever API the user points them at, and lets the AI assistant reach api.moonshot.ai. The hook reads no page content beyond that traffic and does not alter page behavior.

Remote code:
None. All code is packaged with the extension. Responses from Moonshot and from APIs the user calls are data, rendered via textContent — never evaluated or executed.

Data usage — collected or transferred:
Website content (the page's API traffic) is processed locally and stored in the extension's IndexedDB per tab, cleared on each page load unless the user enables "Keep logs on reload", on tab close, and on browser start. It is transferred only (1) to api.moonshot.ai when the user has enabled the optional assistant with their own key and asks it something, solely to answer, and (2) as HTTP requests the user sends or schedules, to the URLs those requests name. The user consents explicitly before the assistant can run, can require a click for requests that change data, and the chat shows exactly what was sent.

Nothing is sold, nothing is shared with any other party, nothing is used for advertising or creditworthiness, and the developer receives no data of any kind.
